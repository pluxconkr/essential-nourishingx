# Glossary

Words you will meet in this project, in plain English.

**Anonymous sign-in** — Supabase creates an account for the phone with a random id and nothing else: no name, email or
student ID. The account still counts as signed in, so the database can keep each student's rows separate.

**Atwater factors** — the standard energy values used to check a meal estimate: 4 kcal per gram of protein and of
carbohydrate, 9 per gram of fat, about 2 per gram of fibre ([sources.md](sources.md)).

**Balance word** — the one word the app shows for your week: *Stable*, *Watch*, *Needs attention*, or *Not enough data*.
It always comes from the rules, never from an AI.

**Bundle** — the single JavaScript file that ships inside the app or website. `npm run check:bundles` checks what is
in it.

**Clause** — one rule in the rule list (A, B1–B3, C1–C6, D). The first clause that matches chooses the word.

**Cohort** — a group of students counted together. Rows are marked `real` or `synthetic` (simulated).

**Edge Function** — a small program that runs on Supabase's servers, not on the phone. NourishingX has three:
`analyze-meal`, `weekly-report` and `delete-me`. Secret keys live there, never in the app.

**Estimate** — a number worked out from a photo, which can be well off. The app shows estimates as ranges and always
labels them; they are never targets.

**Evidence** — the four lines under the word that say which of your inputs the rule looked at.

**Hysteresis** — the "hold" that stops the word flipping daily: it gets worse at once but improves only after three
steadier check-ins.

**JWT (sign-in token)** — a signed note the server gives you when you sign in. It says who you are (`auth.uid()`) and,
for staff, the role in `app_metadata`. The database reads it on every request.

**LLM** — large language model, such as Claude. Here it only looks at meal photos and writes the weekly staff
summary; it never decides a word.

**MAPE** — mean absolute percentage error: on average, how far an estimate is from the true value, as a share of the
true value. 0.40 means "40 % off on average".

**Migration** — a numbered SQL file in `supabase/migrations/` that changes the database. Applied in order with
`npm run db:push`, so every copy of the database ends up the same.

**n ≥ 10 (suppression)** — staff only see a number when at least 10 different students are behind it. Smaller groups
are hidden, because a total of three people can point at one of them.

**Policy (RLS)** — a rule attached to a table that decides which rows a request may read or change.

**Publishable key / secret key** — two kinds of Supabase key. The publishable key is meant to be public and can only do
what RLS allows. The secret key bypasses RLS and must stay on the server.

**Router** — the code that decides which Claude model analyses a photo, based on a quick first look by Haiku.

**Row-level security (RLS)** — the database feature that checks every query row by row against the policies, so a
student's account can only reach that student's rows.

**Security definer** — a database function that runs with its owner's rights. The staff totals use them, in a private
schema, with a staff check on the first line and the n ≥ 10 rule built in.

**Service role** — the Supabase identity Edge Functions use to write rows that no app may write directly (meal
estimates, weekly reports). It never leaves the server.

**Supabase** — the hosted Postgres database, sign-in service and Edge Functions this project uses as its server.

**Synthetic data** — made-up students generated by code (`src/domain/synthetic.ts`) so the dashboard can be built and
shown before any real student uses it. Always labelled.

**Token (AI)** — the unit Claude counts text and images in; costs are charged per million tokens.

**Triage** — the first, fast look at a photo (by Claude Haiku 5.5) that says whether it is food and how hard it is.
